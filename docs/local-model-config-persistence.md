# 本地模型配置持久化

本地桌面模式的模型渠道不再只依赖浏览器 `localStorage`。前端启动时通过 `/api/workspace/model-config` 读取本机快照，渠道发生变化后自动保存；后端将快照原子写入 BeefTV 应用数据目录的 `local-model-config.json`。

- 配置文件位于应用数据目录，不进入 Git，也不随前端静态资源更新覆盖。
- 写入采用临时文件 + `rename`，文件权限为 `0600`，目录权限为 `0700`。
- 同一工作区路径上的多个配置句柄共用一把进程内锁；revision CAS 与脱敏密钥保留跨句柄串行。损坏、`null` 或非对象的现有主文件不会被新写入替换。
- 带 `id` 的渠道只按相同字符串 ID 保留密钥；对不上的脱敏占位会拒绝写入，不会把 A 的密钥写进 B，也不会把占位符存成密钥。
- 工作区路径只把「尚未创建的后缀」当成可恢复；符号链接环或权限/非目录错误会失败，不会为同一目录生成两把锁。
- 内置 BeefAPI 渠道由本机连接流程管理，授权密钥单独加密保存在工作区，不经过模型配置接口、导出或页面。
- 其他手动渠道的 API Key 仍保存在本机配置文件中，不应提交到仓库或日志。
- BeefAPI 可用模型以连接后拉取的目录为准，不在仓库中写死。

首次使用新桌面构建时，如果后端尚无任何快照（健康状态为 `default`）且当前浏览器仍保留渠道配置，前端会把这份本地配置自动迁移到后端快照；后端已有快照（`ready`/`migrated`/`recovered`）时以后端为准，浏览器本地缓存只作展示缓存。因此渠道配置跟随后端数据目录而非某个浏览器，但前提是快照从未在该浏览器成功同步过——若某次会话启动时后端不可用（进入错误页），该会话里的配置改动不会回写。

## 导出与导入（本机编辑配置）

- `GET /api/workspace/model-config/export`：下载解密后的完整配置 JSON（含自定义渠道的 apiKey 明文）。仅限本机或可信内网使用，不要把该端点暴露到公网，也不要把导出文件提交进仓库。
- 编辑后通过 `PUT /api/workspace/model-config` 导入（请求体 `{"config": <导出的 JSON>, "expectedRevision": <GET 返回的 revision>}`）；导入时内置 BeefAPI 渠道的托管密钥会自动保留，冲突返回 409 时重新 GET 获取新 revision 即可。
- 迁移数据目录（换机/重装）时必须同时带走 `local-model-config.json`、`.settings-key` 与 BeefAPI 连接状态文件，缺少 `.settings-key` 时配置无法解密（接口会返回错误，不会静默重建密钥）。

画布助手也从这份快照读取模型和渠道凭据。手动渠道只有 `models` 列表、没有对应 `modelProfiles` 时，助手可跟随已选定的默认文本模型，使用渠道指定的对话协议；OpenAI 格式默认使用 Chat Completions。已声明的能力和协议优先，禁用渠道、非文本模型、不支持的协议或缺少密钥仍不可用。内置托管渠道继续使用其明确的模型目录。
